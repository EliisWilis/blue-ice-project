# Blue Ice Project — Security Module Audit Matrix

**Scope:** Synthesis of the 20-module baseline audit. The baseline classifications below are retained as an audit record, not presented as a fresh review of every source file.

**Implementation update:** Since the baseline, the proxy rechecks final Chat Completions output after placeholder reconstruction and adds a native `/v1/responses` forwarding path for the built-in OpenAI provider and custom providers only when a native `responses_url` is explicitly registered. Responses request limits, local authentication, redaction, tool-output inspection, buffered SSE event replay (including mismatched delta/completion and post-completion regressions), and metadata-only audit have synthetic tests. Blocked/error responses now return `503` if their audit event cannot be written. Path checks now inspect bounded URL-decoded variants and protect selected system roots, `.git` metadata, `.privacyignore`, and Git credential files. Unexpected registry-check exceptions become `verification_unavailable` findings, which the opt-in app policy withholds. These remain bounded proxy checks; they do not complete any of the 20 broader modules, establish live coding-agent compatibility, or change the `partial`/`missing` classifications into `complete`.

**Protocol extension update (26 November 2026):** Initial opt-in forwarding routes now exist for native Anthropic Messages and Gemini GenerateContent; fake-upstream tests check credential separation, fixed destinations, redaction, SSE inspection, and disabled-by-default behavior. The optional MCP stdio server exposes only three read-only project tools and has tests for traversal, symlinks, `.privacyignore`, filename/content redaction, egress rejection, and LLM Guard fail-closed behavior. The optional A2A facade uses the installed SDK's Agent Card and JSON-RPC routes; tests cover card capabilities, CLI-supplied base URL, local auth including `/a2a/`, and one text delegation through the shared gateway. The latest full Python suite reports **80 passed**; Ruff lint/format, compileall, and `git diff --check` pass, as do the TypeScript CLI build and synthetic offline demo. These are local/synthetic tests, not complete third-party client compatibility tests; native SSE is buffered, A2A is text-only and in-memory, and all 20 broader module classifications remain unchanged.

**Interpretation:** “Status” reproduces the audit classification (`partial` or `missing`). “Decision” reproduces the module disposition. `implement_safely` means proceed only within the qualifications and safeguards described below; it does not mean implemented or complete. No module was reported as complete. The supplied `Failures` list is empty: **no audit item was reported as a failed run**. That does not mean the modules pass their proposed tests or meet their specifications.

## Cross-cutting safety limits

- **Controls exist at different maturity levels.** Some narrow controls are implemented and partly integrated (local bearer auth, path-reference checks, secret redaction, output linting, registry checks when enabled). Several helpers are not called by the proxy, and others are absent. Presence of a file or helper is not evidence of active enforcement.
- **The proxy is not an OS sandbox or tool-execution gate.** Path scanning inspects recognizable text references; response screening inspects model output. Neither prevents the CLI/user from reading files or executing commands. Those guarantees require controls at the filesystem and agent/tool execution boundary.
- **Heuristic scanning is incomplete.** Regexes, entropy thresholds, path recognition, package metadata, and injection classification have both false positives and false negatives. They should be described as bounded risk reduction, not comprehensive detection.
- **No strong memory-erasure claim is supported.** Python strings, allocator state, HTTP-client/header copies, process dumps, and operating-system behavior are outside the reach of clearing a dictionary or locking one buffer. Do not promise zeroization, RAM-only storage, or prevention of swap/pagefile persistence.
- **Provider privacy preferences are not provider guarantees.** OpenRouter request preferences do not establish end-to-end zero data retention. Localhost services still receive submitted content. Any provider-side handling depends on provider/account policy.
- **Transformations need exact scope and reversible state.** AST renaming, path aliases, numeric placeholders, canaries, and response reconstruction are not safe to infer from arbitrary chat text. Only restore explicit, collision-checked, request-scoped mappings; leave unknown or altered tokens unchanged.
- **Streaming currently entails buffering for inspection.** Chat Completions SSE is recreated after inspection; Responses SSE frame text is inspected, a terminal completion is required, and later frames are rejected before replay with semantic event names intact. This adds latency, is not incremental gateway streaming, and does not make inspection semantically complete. JSON and SSE both receive post-reconstruction output checks.
- **Audit metadata should remain content-free.** Store bounded rule identifiers/counts and necessary operational metadata only; do not log prompts, source code, credentials, matched values, or reversible maps. Owner-only permissions alone do not make logs immutable or tamper-proof.
- **No report of full completion.** The supplied classifications contain no `complete` status, and the evidence identifies missing implementation or integration for every module. This synthesis makes no claim of complete security or 20/20 implementation.

## Prioritized implementation and test plan

Priorities indicate sequencing for risk reduction and validation, not a declaration that work has been completed.

### P0 — Validate and close gaps in active request/response controls

1. **Authentication boundary (Module 1):** Add acceptance/rejection tests for current bearer auth on protected endpoints, including proof that rejected requests never reach a provider. Keep TCP session capabilities distinct from actual peer-PID authentication; choose a peer-credential transport if OS-level PID binding is required. Document/test `/healthz` policy.
2. **Ingress path policy (Module 3):** The first bounded protected-path rules and tests for broad roots, `.privacyignore`, `.git`, and encoded traversal are now in place. Continue with Windows/UNC, malformed and other encoded variants, and verify fail-closed behavior before provider calls. Do not present the text filter as filesystem confinement.
3. **Secret-redaction path (Module 6):** Expand end-to-end tests for patterns, entropy boundaries, placeholder collisions/expiry, log hygiene, provider-bound payloads, and optional LLM Guard behavior. Define private-address handling as an explicit policy, not an unconditional rewrite.
4. **Final egress inspection (Module 16):** Recheck the final reconstructed assistant text before JSON/SSE delivery; add regression tests for command and URL variants, false positives, and reconstructed-risk cases. Explicitly state that tool-execution sandboxing is outside this control.
5. **Package guard (Module 15):** Unexpected checker exceptions now surface as unverifiable findings and the enabled app path withholds them. Continue testing real timeout/response boundaries and unsupported Cargo/Go behavior. Clearly distinguish response-text checks from actual install interception.

### P1 — Integrate or explicitly defer existing but disconnected helpers

1. **AST anonymizer and reconstruction (Modules 7 and 19):** Pin compatible parser/grammar dependencies, use explicit opt-in and scope-aware transformations, add request-scoped reverse-map plumbing only after verification, and test actual ingress/egress integration. Otherwise report anonymization as unavailable.
2. **Hybrid summarizer (Module 13):** Define a model-aware token threshold, opt-in policy, local-recipient disclosure, bounded outputs, preservation/fallback rules, and proxy integration tests with fake Ollama clients. Do not promise fixed token savings.
3. **Split inference and routing (Module 11 and 14):** Keep disabled until explicit semantic subrequests, provider authorization, credentials, failure behavior, and local composition checks are designed and tested. Treat privacy preferences as preferences, not ZDR; do not silently fail over.
4. **Honey token (Module 10):** Keep disabled unless a specific diagnostic use is approved. Validate private audit storage and test no content/key logging. Label any match as an observation, not proof of training.
5. **Registry cache and quota helper (Modules 14 and 15):** If retained, wire bounded state with freshness/expiry and test its real app integration; otherwise avoid presenting helpers as operational routing or caching controls.

### P2 — Add absent features only after threat model and interface design

1. **Git-history guard (Module 4):** Define that the proxy can scan only Git-like content present in the request unless a trusted repository interface is added. Reuse generic redaction; prove incremental coverage and pre-provider blocking.
2. **Indirect-injection handling (Module 5):** Add explicit untrusted-span provenance at the ingestion boundary; target only documented Unicode controls while preserving valid multilingual text. Pair with tool authorization rather than claiming sanitizer guarantees.
3. **Topology scrubber (Module 8):** Defer until typed file inputs and format-aware semantics exist. Preserve licenses, directives, and behavior-visible docstrings by default; test exact reversible aliases.
4. **Encoded-output detector (Module 17):** Set bounded decoder/size limits and candidate policies; compare only against a defined sensitive baseline and use configurable review/block behavior. Test ordinary hashes, fixtures, and false-positive cases.
5. **Snapshot/rollback (Module 18):** Implement at the workspace write boundary, not as a proxy-only feature. Use durable snapshot identifiers, dry-run/conflict checks, root confinement, explicit confirmation, and dirty-tree preservation tests.
6. **Provenance signing (Module 20):** Only if a verifier/use case is defined, specify canonical final response bytes, separate protected key storage, log failure policy, key rotation, and JSON/SSE semantics. Describe HMAC as shared-key integrity attestation, not authorship.
7. **Jitter and numeric transforms (Modules 12 and 9):** Treat jitter as limited timing noise with bounded deadlines and no model-visible padding. Do not implement reversible numeric scaling as differential privacy; any numeric placeholders must be explicitly scoped pseudonymization with exact restoration tests.
8. **Memory hardening (Module 2):** Improve credential lifetime and keyring handling first. Any locked mutable buffer is best-effort and must be documented with platform limitations; test its exact buffer lifecycle without inferring process-wide no-swap guarantees.

## Explicitly failed or unresolved items

**Failed audit runs:** None reported (`Failures: []`). This means there were no reported audit-execution failures; it does not indicate passing implementation tests.

**Unresolved implementation scope:** All 20 modules remain unresolved relative to their requested target state. Modules **1, 2, 3, 6, 7, 10, 11, 13, 14, 15, 16, and 19** are classified `partial`; modules **4, 5, 8, 9, 12, 17, 18, and 20** are classified `missing`. Module 9 is specifically `do_not_implement_as_written`; the proposed reversible scaling must not be represented as differential privacy. Existing partial controls should be retained and accurately scoped while missing integration, boundaries, and tests are addressed.
